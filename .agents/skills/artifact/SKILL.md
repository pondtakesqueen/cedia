name: artifact
description: Decide when session output should become a shareable page (Docs, Slides, Design, Dashboard, custom) and how to shape it agent-side; cedian owns rendering and storage. Use when output is easier to see than read, or the user names a template.
argument-hint: <brief or template>
---

Agent-side only. Never store, host, or render. Write the source file, declare what the page needs at publish, hand the rest to cedian.

1. When to create. Significant and self-contained (typically over 15 lines), worth editing, iterating, or reusing outside the conversation, stands alone without conversation context, likely to be referred back to. Explicit ask always wins ("create this as an artifact", "as a deck", "as a doc"). Template pick wins over auto-choice.
2. Page or document. Explainers and visual or interactive work become artifact pages. Documents are for writing people keep editing or pass around. Name the kind in the request when unsure ("make this a Slides deck", "give me this as a file for PowerPoint").
3. Kind mapping. Docs: living document, co-edited in real time, comments with @Claude, export docx/Google Docs. Slides: `/slides <brief>` with audience, edit slide by slide, present in place, export pptx/PDF/Slides. Design: `/design <brief>`, artboards on a canvas, drag/resize/align, honours the project's design system. Dashboard (beta, paid): charts from connected tools, snapshot by default, refresh on ask; live-refresh declarations name the connector. Motion (beta, Team/Enterprise): animated explainer, MP4 export — deferred to cedian, do not promise it here. Custom: tracker, quiz, planner, intake form; saves entries, connects tools, may offer a file download button. Code, single website, image, diagram, small tool: single page. Debate-style practice (research brief, opponent rounds, feedback): loops go through thread turns, never in-page Claude calls in v1.
4. Design system lookup. Before choosing palette, type, or spacing, read CLAUDE.md and AGENTS.md for tokens (colors, fonts, spacing, radius). Prompt beats system, system beats defaults. Typefaces: Google Fonts only as an external source, every face with a fallback stack; anything else inlined as @font-face data URI.
5. Interview before build. Who uses it, what it must show, where numbers come from, who reads it, what good looks like. Ask when the brief is thin. Save a repeatable process as its own skill (sources, kind, audience, checks).
6. File contract (what publish enforces). Outside the project temp dir, `.html`/`.htm`/`.md`, UTF-8 (UTF-16 only by BOM, never U+FFFD), single file, inline CSS/JS, images as data URIs, multi-section via `#anchor` links (relative links do not resolve), rendered page 16 MiB or smaller. Scripts only from cdnjs, unpkg, Tailwind CDN, jQuery CDN, selected jsdelivr `/npm/` paths — pin exact versions at least two weeks old. No Print buttons, confirm dialogs, or device features the viewer blocks. No backend, no auth in the page, no self-started downloads (declare the downloads capability instead).
7. Chaining. Build the next artifact from this one without re-explaining ("turn this doc into a six-slide deck", "make a one-pager from this deck"). Duplicate before a big rework so versions can be compared.
8. Publish and update. First publish prints the URL. Update means edit the source file and republish to the same id; each publish is a version, viewers pick which version they see. From another session, update by URL or attach, otherwise a new artifact results. A stale-base publish is refused until the newer page is merged. Never overwrite a source file not re-read since it changed.
9. Redaction edge cases. Parser-heavy work (redaction, placeholders, bare lines, trailing newlines) gets extra scrutiny: prove each edge with a passing test rather than adjusting the source to satisfy a corrupted expectation.
