Guidance for coding agents working in this repository. `CLAUDE.md` points here.

## What this is

cedia is a personal coding harness written from scratch in TypeScript on Bun. `SPEC.md` holds every settled decision and the stage order; read it before changing scope. `docs/ROADMAP.md` says what comes next.

## Commands

- `bun test`: all tests. One file: `bun test test/layers.test.ts`. One test: add `-t "<name>"`.
- `bun run typecheck`: `tsc --noEmit`.
- `bin/cedia -p "<prompt>" [-m <model>] [--output-format text|json|stream-json] [--permission read-only|workspace] [--allow <rule>] [--deny <rule>]`: headless run. Read-only unless `--permission workspace`. `--check <cmd>` declares a check for the done gate. `--goal <condition>` keeps the run going until a separate judge finds the condition holds (`--goal-judge <ref>`; `--goal-mode full` adds acceptance criteria first and a strategist when the same ones stay unmet). `--sandbox auto|on|off` controls the OS sandbox for bash (Linux needs bubblewrap, socat, ripgrep). `--fallback <ref|none>` names the model a run continues on when its quota runs out (default: Haiku on OpenCode Go → `anthropic/claude-haiku-5-5`, the same model on the Claude API); `--on-quota wait:<min>` waits up to that long for a quota that says when it resets before falling back. The code model defaults to `haiku` (Haiku 5.5 through OpenCode Go, starting at effort medium: `evals/results/2026-10-29-haiku-effort/`). `--effort <level>` sets where the writer starts and `--escalate <level|off>` (default high) where it moves, once, when the done gate refuses a claim (Claude 5.5 models; a per-message effort change, so the cache stays). `--plan <ref>` and `--review <ref>` add the plan and review roles (with `--spawn worktree`, the planner may split the work into parts that cedia hands to work sub-threads before the writer starts, each on the code model or one of `--workers <ref,...>`), `--advisor <ref>` a model that reads each writer turn and may leave a note, `--classifier <ref>` a model that reads each command no allow rule names and may block it (`claude-code[:<model>][@<effort>]` runs them in the user's own Claude Code; opus at medium by default); `roles` in `~/.cedia/settings.json` sets all three. `CEDIA_CLAUDE_BIN` points tests at a fake `claude`. Every run is a thread of the project: `--thread <id>` goes on with one, `--handoff-at <n|off>` sets when a long session hands off to a new one, `--handoff compact|note` how (compact, the default: Anthropic's server compaction keeps the newest turns, on Claude API models; the note elsewhere), `--spawn on|off|worktree` and `--swarm <ref>` control sub-threads (worktree: each work sub-thread in a git worktree of its own, several at once). `--plan-overlap on|off` (`planOverlap` in settings; default on: the writer reads while the plan is written and the plan follows into its session, `evals/results/2026-10-28-overlap/`). `--plan-when auto|always|never` (`planWhen` in settings; default auto: the `--triage` model, default the code model, says first whether a message needs the planner, so a greeting or question skips it; `/plan` and `/quick` in the TUI). `-m auto` plans with `claude-code:opus@low` and reviews with `claude-code:sonnet@high` where no plan or review role is set (`evals/results/2026-10-29-cheaper-opus/`, `evals/results/2026-10-29-auto/`). A cedia plan or review model takes `@<effort>`. `--cache-ttl 5m|1h` sets how long the writer's cached prompt lasts on the Anthropic wire (default 5m; the TUI uses 1h). `--lsp on|off` (default on) adds a language server's errors to each edit's result when one is installed. `--ask on` gives the writer `ask_user`, which ends the run with one question for the owner (thread state `asking`; the answer is the next prompt). `--image <file>` (repeatable) shows the writer an image with the prompt, or a video as up to 8 frames taken with ffmpeg where the screen changes (`core/video.ts`), and `read` opens image and video files; a run with images on a text-only code model runs on `--media <ref|none>` (default `anthropic/claude-haiku-5-5`); `grep` searches with ripgrep, `core/tools/grep.ts` (`core/images.ts`; blobs in `~/.cedia/blobs`). `--todo on` gives it `todo`, a list of steps kept in the thread as its progress. `--browser <endpoint>` gives it `browser`, a page of a Chromium the client started, driven over its DevTools endpoint (`core/tools/browser.ts`; `test/browser.test.ts` runs a real Chromium when one is installed, `CEDIA_CHROMIUM` names it). `--profile <name>` lays a named set of defaults under the flags (`profiles` in settings; built in: `coordinator`, which opens queued threads with `open_thread`, and `ci`, for the PR watcher's failed-check prompts: no planner, a workspace session and the rules for such a fix; a profile may set `planWhen`). `CEDIA_ROOTS=<primary>:<root>...` makes the project a multi-repo workspace: every root is filed under the primary root's slug, `open_thread` takes a `root`, a `--thread` run goes on in its thread's root, and the writer is told the other roots are read-only (`test/workspace.test.ts`).
- `bin/cedia` with no prompt, at a terminal: the TUI (`src/clients/tui-ink/`, on Ink). Each prompt is a turn of one thread on the `-p` path; `/help` lists its commands. `test/tui-ink-*.test.ts` cover it offline; `test/tui-ink-boot.test.ts` smoke-tests it.
- `bin/cedia threads [list [--all] | show <id> | send <id> <text> [--image <file>]... | unsend <id> [<msg>...] | rate <id> <up|down> | archive <id> | rename <id> <title> | delete <id> [--force] [--json] | diff <id> | undo <id> | redo <id> | rewind <id> [<n>] | fork <id> <n|run|end> [--side] [--json]]`: the project's threads. `undo` and `redo` move the files of the thread's last turn that changed files, from the shadow snapshots (`--json`: `Restored`); `rewind` takes the thread back to just before run n, conversation and files together (`--json`: `RewindResult`, a refusal with `force` when `--force` goes past it); `fork` opens a new thread from the conversation just before run n and leaves the original and the files alone (edit and resend); `fork <id> end --side` is a side chat, the thread as it stands now in a thread `list` leaves out; `rename` logs a `title` event; `delete` removes the thread, its sub-threads and their session logs for good (`--json`: `DeleteResult`).
- `bin/cedia inline-edit --file <path> --range <line:col-line:col> --instruction <text> [--stdin] [--model <ref>] --json`: the desktop's Cmd+K, a selection's new text and its patch (`InlineEdit`), nothing written (`core/project/inline-edit.ts`).
- `bin/cedia review --thread <id> [--model <ref>] --json`: the desktop's /code-review card, a read-only review of what the thread changed, its findings by file and line (`CodeReview`, `core/project/code-review.ts`).
- `bin/cedia schedules [list | due | add <when> <prompt> --thread <id> [--every <dur>] | cancel|pause|resume|fire <id>] [--json]`: the project's scheduled prompts. cedia only says what is due; the desktop's daemon (or cron) fires and runs each one.
- `bin/cedia memory [list | add <text> | forget <id>]`: the project's memory, which every new session gets in its first turn.
- `bin/cedia models [--json]`: the models a session may use, and the modes `auto` and `oplan` (`-m auto|oplan`, `modeFlags` in `core/config.ts`) (`core/providers/models.ts`), which have a key here (env or Keychain), the effort levels each takes and where a run starts without `--effort`, and `default`, the one the code role takes now; for a client's model picker. The JSON is `ModelList` in the protocol schema.
- `bin/cedia permissions [--json]`: the permission modes a run may take (`--permission auto|read-only|plan|workspace`) and the default, for a client's picker. `plan` is read-only and ends with a plan and `ask_user` for the go-ahead.
- `bin/cedia commands [--json]`: what a client offers for `/`: each skill here (`CommandList`). A prompt that starts with `/<skill>` asks the writer to load that skill first.
- `bin/cedia skills`: the skills a session here can load (`~/.cedia/skills`, and the repository's `.agents/skills`, `.claude/skills`, `.cursor/skills`); the model loads one with the `skill` tool.
- `bin/cedia plugin [list | install <folder|git-url|github:owner/repo|plugin@marketplace> | show <name> | mcp <name> | enable|disable|uninstall|update <name>]` and `bin/cedia marketplace [list | add <name> <source> | remove <name>]`: Claude Code-layout plugins in `~/.cedia/plugins`; their skills and commands become `<plugin>:<name>` skills, their MCP servers start only after `plugin mcp`, their hooks and agents never run (`core/plugins/plugins.ts`, `test/plugin.test.ts`).
- MCP servers come from `mcpServers` in `~/.cedia/settings.json` only (`src/core/mcp/`); `test/mcp/server.ts` is a fake stdio server for tests. `bin/cedia mcp [list | check <name> | add <name> (--command <cmd> [--arg <a>]... [--env K=V]... | --url <url> [--header K=V]...) [--read-only] [--timeout <sec>] | remove <name>] [--json]` manages them for a client's settings page (`core/mcp/manage.ts`; `McpList` names env variables and headers, never their values; `McpCheck` starts one and lists its tools).
- `bin/cedia --version --json`: version, protocol schema hash and capabilities, for clients.
- `bin/cedia usage [<file.jsonl>... | --thread <id> | --last <n> | --since <YYYY-MM-DD|Nd>] [--all] [--json]`: where a project's spend went, from its session logs: input by source (counted each time a request resent it), the costliest tool results, cache misses by cause, requests past a long-context price line or at effort max, handoffs, and the cost by local day, model, project and thread (`--since` reads every session in the range and bills only from its start; `--all` reads every project). A run's JSON result names its own misses in `cacheMisses`.
- `bin/cedia lint-session <file.jsonl>...`: check a session log against the trust invariants. `-m faux` with `CEDIA_FAUX_SCRIPT=<steps.json>` runs offline.
- `bun scripts/protocol-schema.ts` regenerates `src/protocol/protocol.schema.json` after a protocol type changes; `bun scripts/session-fixtures.ts` re-records `test/fixtures/sessions/` after the output of a run changes. `test/fixtures.test.ts` fails when either is stale.
- `bun scripts/cache-probe.ts --model <ref> [--turns 20] [--runs 3]`: measure prompt-cache hits on a real model and name every miss.
- `bun evals/run.ts --harness <name> [--model <ref>] [--runs 3] [--jobs 4] [--budget <usd>] [--only <ids>] [--cedia-arg=<flag>]`: run the eval tasks against a harness; `--estimate --model <ref> [--measured <results.jsonl>]` prices a run first. Binaries come from `CEDIA_EVAL_<NAME>_BIN` or PATH. Results go in `evals/results/`.
- `bun evals/gate.ts [--model <ref>] [--estimate] [--update-baseline]`: the regression gate. Runs `evals/gate/suite.json`, prints the expected cost first, compares with `evals/gate/baseline/` and exits 1 when a model got worse. `--compare <results.jsonl>` re-scores a result file for free. Run it before merging a change to a prompt, default, the loop, a tool or the trust layer (`evals/gate/README.md`).

## How to work

Work the pstack poteto-mode way:

- Name the data shapes before writing logic.
- Prove it works: every done-criterion has a test or a command that reruns.
- Decide by experiment (prototype or eval) instead of asking when the question can be measured.
- Small commits, each one a unit that can be checked.
- Commit messages carry Verify (the test or command that reruns the done-criteria) and Risk (low/medium/high per the code-review skill's tier paths, and whether a person still needs to see it).

## Rules that are easy to get wrong

- `src/core` and `src/protocol` never import from `src/clients`. `test/layers.test.ts` enforces it.
- Model-visible means logged: anything that reaches the model is an event in the session log first.
- Keep the cached prefix byte-identical (see "Cache rules" in `SPEC.md`). Never edit message 0 mid-session.
- Every `tool_use` gets a `tool_result`, including denied and not-started calls.
- API keys only. Never add Claude.ai OAuth, Cursor login, or any request that impersonates another client.
- Never copy code or prompts from `anthropics/claude-code` (no license) or leaked sources, and never port cedia-rs. Adapted Apache-2.0/MIT code needs a `NOTICE` entry.
- e2e tests use the faux provider and must work offline.
